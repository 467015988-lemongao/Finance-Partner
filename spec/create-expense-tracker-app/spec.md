# 生活记账应用 Spec

## Why
用户需要一个用于记录每日生活成本的小应用：能快速记一笔、按自己的消费习惯自定义记账类目，并能在 Web（桌面）与 App（移动端）两端随时查看账目明细和对数据的统计分析。当前仓库没有记账相关代码，需要一套可直接运行、前后端完整的最小可用实现。

## What Changes
- 新增后端服务目录 `expense-tracker-server/`：基于 Express + JSON 文件持久化，提供类目、账目、统计三类 REST API
- 新增 Web 端目录 `expense-tracker-web/`：Vue 3 + Vite + ECharts，桌面优先布局（侧边导航），面向大屏查看明细与图表
- 新增 App 端目录 `expense-tracker-app/`：Vue 3 + Vite，移动端优先 H5，支持 PWA（可添加到手机主屏），底部 TabBar 导航
- 双端共用同一份后端数据，不引入账号/登录体系（单用户）
- 支持用户新增、编辑、删除自定义记账类目（内置默认类目）
- 支持统计：月度概览指标、类目占比饼图、每日趋势、近 6 个月趋势
- 不改动仓库现有 `newyear-2027-*`、`mooncake-*` 等任何既有项目

## Impact
- Affected specs: 无（全新独立应用）
- Affected code:
  - 新增 `expense-tracker-server/`（`server.js`、`data/` 数据目录）
  - 新增 `expense-tracker-web/`（`index.html`、`vite.config.js`、`src/`）
  - 新增 `expense-tracker-app/`（`index.html`、`vite.config.js`、`public/manifest.webmanifest`、`src/`）
  - 不修改任何现有目录文件

## 数据模型与约定

### 类目 Category
```json
{
  "id": "c_1700000000000",
  "name": "餐饮",
  "icon": "🍜",
  "color": "#ff7a45",
  "isDefault": true,
  "createdAt": 1700000000000
}
```

### 账目 Record
```json
{
  "id": "r_1700000000000",
  "amount": 32.5,
  "categoryId": "c_1700000000000",
  "date": "2026-11-08",
  "note": "午餐",
  "createdAt": 1700000000000
}
```

### 全局约定
- 金额单位：元，最多两位小数，必须大于 0；后端统计一律换算为「分」做整数运算，避免浮点误差
- 日期格式：`YYYY-MM-DD`（本地时区）
- 数据持久化：`expense-tracker-server/data/categories.json`、`expense-tracker-server/data/records.json`，启动时若不存在则用默认类目初始化
- 端口：后端 `3010`（3001 被仓库旧服务占用，支持 `PORT` 覆盖），Web 端 `5175`，App 端 `5176`
- 后端统一响应格式：成功 `{ "ok": true, "data": ... }`，失败 `{ "ok": false, "error": "错误说明" }`
- 参数校验失败返回 `400`，资源不存在返回 `404`，业务冲突（如删除有记录的类目）返回 `409`

## ADDED Requirements

### Requirement: 记账类目管理
系统 SHALL 允许用户查看、新增、编辑、删除记账类目，并在首次启动时提供一组内置默认类目。

#### Scenario: 首次启动初始化默认类目
- **WHEN** 后端首次启动且 `data/categories.json` 不存在
- **THEN** 自动生成默认类目：餐饮、交通、购物、居住、娱乐、医疗、其他，均带图标与颜色，`isDefault` 为 `true`

#### Scenario: 新增类目
- **WHEN** 用户提交类目名称、图标（emoji）、颜色
- **THEN** 后端校验名称非空且不与现有类目重名，创建成功后返回新类目，双端类目列表同步可见

#### Scenario: 名称为空或重复
- **WHEN** 用户提交空名称或与已有类目重名
- **THEN** 后端返回 `400`，前端提示"类目名称不能为空"或"该类目已存在"

#### Scenario: 编辑类目
- **WHEN** 用户修改类目名称、图标或颜色并保存
- **THEN** 类目更新成功，已有账目仍关联该类目，双端展示为新名称与新颜色

#### Scenario: 删除无记录的类目
- **WHEN** 用户删除一个未被任何账目引用的类目
- **THEN** 删除成功，列表立即刷新

#### Scenario: 删除有记录的类目
- **WHEN** 用户删除一个仍被账目引用的类目
- **THEN** 后端返回 `409` 及引用笔数，前端提示"该类目下存在 N 笔记录，无法删除"

#### Scenario: 至少保留一个类目
- **WHEN** 用户尝试删除最后一个类目
- **THEN** 后端拒绝并提示"至少保留一个记账类目"

### Requirement: 记账（新增账目）
系统 SHALL 允许用户记录一笔支出，包含金额、类目、日期、备注。

#### Scenario: 快速记一笔
- **WHEN** 用户填写金额、选择类目（日期默认今天）并提交
- **THEN** 账目落库成功，列表与统计即时更新，Web 端表单重置，App 端展示保存成功反馈

#### Scenario: 金额校验
- **WHEN** 用户输入的金额为空、为 0、为负数、超过两位小数或非数字
- **THEN** 提交被拒绝，前端提示"请输入大于 0 的金额（最多两位小数）"

#### Scenario: 类目与日期校验
- **WHEN** 未选择类目或提交的类目不存在，或日期格式非法
- **THEN** 后端返回 `400`，前端提示对应错误

#### Scenario: 备注长度限制
- **WHEN** 备注超过 50 个字符
- **THEN** 后端返回 `400`，前端提示"备注最多 50 个字符"

### Requirement: 账目明细管理
系统 SHALL 提供账目明细的查询、编辑与删除能力。

#### Scenario: 按月份查看明细
- **WHEN** 用户选择某个月份
- **THEN** 列表按日期倒序分组展示该月账目，每笔显示类目图标与名称、备注、金额、日期，并展示该月合计

#### Scenario: 筛选与搜索
- **WHEN** 用户选择类目筛选或输入备注关键词
- **THEN** 列表仅展示匹配的账目，条件可组合，清空条件后恢复全量

#### Scenario: 编辑账目
- **WHEN** 用户修改某笔账目的金额、类目、日期或备注并保存
- **THEN** 更新成功，列表与统计同步刷新

#### Scenario: 删除账目
- **WHEN** 用户删除某笔账目并确认
- **THEN** 该账目被移除，列表与统计同步刷新

#### Scenario: 空数据
- **WHEN** 当前筛选条件下没有任何账目
- **THEN** 展示空状态提示"暂无账目记录"

### Requirement: 统计分析
系统 SHALL 对账目数据提供统计分析，包含月度概览、类目占比、每日趋势与近 6 个月趋势。

#### Scenario: 月度概览指标
- **WHEN** 用户查看某个月份的统计
- **THEN** 展示该月总支出、记账笔数、日均支出（按当月已过天数计算）、相对上月的变化百分比

#### Scenario: 类目占比
- **WHEN** 用户查看某个月份的统计
- **THEN** 以饼图展示各类目支出金额与占比，按金额从高到低排序，并展示类目图例

#### Scenario: 每日趋势
- **WHEN** 用户查看某个月份的统计
- **THEN** 以柱状图展示该月每天的支出金额，无支出的日期显示为 0

#### Scenario: 近 6 个月趋势
- **WHEN** 用户查看统计页
- **THEN** 以柱状图展示截至所选月份最近 6 个月的总支出，便于观察长期变化

#### Scenario: 无数据统计
- **WHEN** 所选月份没有任何账目
- **THEN** 指标显示 0，图表展示空状态提示，不报错

### Requirement: Web 端（桌面优先）
系统 SHALL 提供桌面优先的 Web 端，采用侧边导航 + 主内容区布局，包含记账、明细、统计、类目四个页面。

#### Scenario: 桌面布局
- **WHEN** 用户在桌面浏览器打开 Web 端
- **THEN** 左侧固定侧边导航（记账 / 账目明细 / 统计分析 / 类目管理），右侧主内容区自适应宽度

#### Scenario: 记账页
- **WHEN** 用户进入记账页
- **THEN** 表单与当日/本月最近账目并列展示，提交后无需跳转即可看到新增结果

#### Scenario: 统计页图表
- **WHEN** 用户进入统计分析页并切换月份
- **THEN** 指标卡与 ECharts 图表随月份联动刷新，窗口尺寸变化时图表自适应

#### Scenario: 后端不可达
- **WHEN** 后端服务未启动或请求失败
- **THEN** 页面展示明确的错误提示与"重试"按钮，不白屏

### Requirement: App 端（移动端 H5 / PWA）
系统 SHALL 提供移动端优先的 App 端，采用底部 TabBar 导航，可作为 PWA 添加到手机主屏。

#### Scenario: 移动端布局
- **WHEN** 用户在手机浏览器打开 App 端
- **THEN** 页面宽度自适应，底部固定 TabBar（记一笔 / 明细 / 统计 / 我的），触摸区域不小于 44x44px

#### Scenario: 记一笔
- **WHEN** 用户进入「记一笔」页
- **THEN** 金额为页面主视觉输入，类目以图标网格选择，日期默认今天，保存后给出成功提示并重置表单

#### Scenario: 明细页
- **WHEN** 用户进入「明细」页
- **THEN** 支持左右切换月份，按日期分组展示账目，点击账目可编辑，左滑可删除

#### Scenario: 统计页
- **WHEN** 用户进入「统计」页
- **THEN** 展示月度指标卡、类目占比环形图与每日趋势图，图表适配窄屏

#### Scenario: 我的页（类目管理）
- **WHEN** 用户进入「我的」页
- **THEN** 可查看并管理全部类目，支持新增、编辑、删除，交互使用底部抽屉式弹层

#### Scenario: 添加到主屏
- **WHEN** 用户通过手机浏览器访问并选择「添加到主屏幕」
- **THEN** 应用以独立窗口启动，图标、名称、主题色来自 `manifest.webmanifest`

#### Scenario: 深色模式
- **WHEN** 手机系统处于深色模式
- **THEN** App 端背景、卡片、文字自动切换为深色主题

### Requirement: 双端数据一致性
系统 SHALL 让 Web 端与 App 端读写同一份后端数据。

#### Scenario: 跨端同步
- **WHEN** 用户在 App 端新增一笔账目，随后在 Web 端刷新明细
- **THEN** Web 端能看到该笔账目，统计结果一致

#### Scenario: 并发写入
- **WHEN** 两端几乎同时写入
- **THEN** 后端串行落盘，两个文件写入使用临时文件 + 重命名保证不产生损坏的 JSON
